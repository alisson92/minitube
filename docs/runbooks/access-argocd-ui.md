# Runbook — ArgoCD UI access

## How the password is set

`terraform/envs/lab/argocd.tf` generates the `admin` password via `random_password.argocd_admin` and injects the corresponding bcrypt hash directly into the `argo-cd` chart values (`configs.secret.argocdServerAdminPassword`/`argocdServerAdminPasswordMtime`, via `terraform_data.argocd_admin_password_hash`) — the same mechanism already used for the Grafana password (ADR 011, decision 12). The plaintext value is never committed: it only lives in the Terraform state (remote S3 backend), read via `terraform output`.

Pre-seeding the password this way means ArgoCD **never** creates the `argocd-initial-admin-secret` Secret (that secret is only generated by the chart when no admin password already exists in `argocd-secret`) — that's why the old command (`kubectl get secret argocd-initial-admin-secret`) no longer works; always use the `terraform output` below instead.

Since `envs/lab` is recreated from scratch every session, the password changes with every `terraform apply` (a new run of `random_password.argocd_admin`) — there's no fixed `admin/admin` across sessions, only within the same one.

## Command

```bash
cd terraform/envs/lab
AWS_PROFILE=cloudlab terraform output -raw argocd_admin_password && echo
```

- **URL:** `https://argocd.minitube.projetodevops.com.br`
- **User:** `admin`
- **Password:** output of the command above

## Note on rotation

Changing the password via the ArgoCD UI/CLI (`argocd account update-password`) overwrites the hash in `argocd-secret` directly on the cluster — the `terraform output` value becomes stale from that point on (Terraform is unaware of the change, and a `terraform apply` with no other change to the state won't revert it, thanks to `lifecycle.ignore_changes` on `terraform_data.argocd_admin_password_hash`). Since the environment is destroyed and recreated every session, this rarely matters in practice — but it's worth knowing so you're not surprised if the `terraform output` password stops matching the one actually active.
