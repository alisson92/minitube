Kickoff

The edge and the network

A CDN exists for one reason: die at the edge before you ever reach the origin. Almost every request in this system is designed to never leave CloudFront.

Request path — video vs. operational traffic

→
default behavior ↓
/api/* · uncached ↓ ↓
╌╌ bypasses CloudFront ╌╌▸
  • One NAT Gateway, not one per AZ — a deliberate cost trade-off, documented as a single point of egress, not an oversight.
  • The SPOT node group is pinned at 3 nodes — the real ceiling measured here is IP addresses per t3.medium (VPC CNI), not CPU headroom.
  • Video never touches the ALB. CloudFront reads the HLS bucket directly; only upload and status calls cross into the cluster.
  • Operational UIs skip the CDN entirely — Argo CD and Grafana go straight to the ALB, since caching a dashboard helps no one.
  • One wildcard certificate, issued once in a persistent stack — the ephemeral environment only ever reads it, never reissues it.

The Squad

GitOps and the platform

Nothing here is deployed by hand. If it's running, it's because Git says it should be — Argo CD is the only thing allowed to talk to the cluster's API on a normal day.

Reconciliation — from a commit to a running pod

→ →
ns: minitube-app ↓
ns: minitube-platform ↓
ns: argocd ↓
  • App of Apps — one Helm release, declared by Terraform, creates all 10 Applications at once.
  • Every add-on shares one shape: the official upstream chart plus this repo's own values file — no forks, config stays in Git.
  • kube-prometheus-stack needs server-side apply — the Prometheus Operator's CRDs are too large for kubectl's default.
  • Argo CD is the one exception to "everything is GitOps" — it can't reconcile its own installation before it exists.

Playback — the fork the CDN exists to win

✓cache hit → served at the edge, S3 never touched
·cache miss → CloudFront fetches once, then caches
  • The transcoder is a Kubernetes Job, not a long-lived service — one-shot work, self-cleaning via TTL, no external scheduler.
  • One shared IRSA role for both the API and the transcoder — pod identity, scoped to exactly the S3 actions needed, no static credentials anywhere.
  • Raw uploads are never public. The bucket policy only lets CloudFront read hls/* — the original file is unreachable outside this exact path.
  • The X-Cache header is the real proof the CDN is doing its job — not a "distribution: Deployed" status check.

Extra Time

Autoscaling and observability

The real test was never whether it works — it's what happens when a crowd shows up at once.

Load, scale, and everything watching

→
scaling ↓
metrics ↓
logs ↓
AWS-managed ↓
everything converges on
  • Autoscaling is CPU-based (HPA), not node-level — the measured bottleneck was one replica's CPU, so scaling pods solved the actual problem.
  • k6 runs from inside the VPC — the client's own network path was masking the platform's real capacity ceiling.
  • Loki stays single-binary — no gain from a distributed log store in an environment torn down every session.
  • Load-tested to 800 req/s against the API, combined traffic peaking well above that — HPA held the line, 2 → 3 → 5 → 6 replicas, latency queued under saturation but zero request failures.
